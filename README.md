# סימולטור שכר

מחשבון שכר מלא הבנוי על טבלאות הסימולציה הרשמיות שבתיקיית **«נתונים למערכת»**.
המערכת שואבת את הנתונים ישירות מקבצי ה-PPTX/DOCX, מחשבת שכר לכל צירוף של
מקצוע · מחוז · רמת פעילות · ותק · גמול השתלמות, ומציגה פירוט מלא של מקור כל שקל.

---

## הרצה מהירה

```bash
# 1. בניית מאגר הנתונים מקבצי המקור
python3 tools/build_dataset.py

# 2. בניית עמוד המחשבון
python3 tools/build_web.py

# 3. פתיחה בדפדפן
xdg-open index.html          # או פשוט לפתוח את הקובץ ידנית
```

או בפקודה אחת: `make`

---

## שלושה ממשקים

### 1. עמוד ווב (`index.html`)

קובץ HTML **עצמאי לחלוטין** — בלי שרת, בלי אינטרנט, בלי ספריות חיצוניות.
אפשר לשלוח אותו במייל או להעתיק ל-Disk-on-key והוא יעבוד.

כולל: בחירה מדורגת של מקצוע/מחוז/רמת פעילות, סרגל ותק רציף, מתגי גמול
השתלמות ושירות בתחנה, פירוט חישוב מלא, גרף התקדמות לפי ותק, טבלת נקודות
העוגן מהמקור, ואומדן נטו אופציונלי. תומך במצב כהה.

### 2. שורת פקודה

```bash
python3 -m salary_calc.cli --list                 # כל המקצועות והאפשרויות

python3 -m salary_calc.cli \
    --profession investigator --district ירושלים \
    --seniority 2.5 --station --gemul gemul_a --net

python3 -m salary_calc.cli --manager-group 6 --rating "אקדמאי ישים 7%" --seniority 1
python3 -m salary_calc.cli --lod --rifleman
python3 -m salary_calc.cli --profession magav_fighter --activity "א'" --curve
python3 -m salary_calc.cli --profession yasam_patrol --district דרום --json
```

### 3. ספריית פייתון

```python
from salary_calc import load_dataset

ds = load_dataset()
r = ds.calculate_field(
    profession_id="investigator",
    district="ירושלים",
    activity_level="שיטור חדש",
    seniority=2.5,
    gemul="gemul_a",
    in_station=True,
)

print(r.monthly_gross)      # 13368.5
print(r.annual_gross)       # 160422.0
for c in r.breakdown.components:
    print(c.label, c.amount)
```

## מה המערכת מכסה

| מסלול | מקורות | מה נכלל |
|---|---|---|
| **מקצועות שטח** | 4 מצגות רפרנטים (ותק 0/1/2/3) | 7 מקצועות, 25 וריאנטים של מחוז × רמת פעילות |
| **מנהלים** | 4 מצגות מנהלים (ותק 0/1/2/2.8) | קבוצות שכר 1–8 × 3 דירוגים |
| **יס"מ תחנת לוד** | מצגת ייעודית | ותק 2.8, עם/בלי רובאי 05 |
| **מחוז ירושלים** | מסמך 14.7.2025 | שירות בתחנה מול לא בתחנה |
| **שיוך מג"ב** | «סימולצית שכר מגב» | 13 מרחבים × 6 תפקידים → רמת פעילות |

**מקצועות:** סייר/בלש (במסגרת קפ"ז ומחוצה לה) · חוקר (במסגרת קפ"ז ומחוצה לה) ·
סייר יס"מ · מוקדן 100/משגר · לוחם/סייר מג"ב.

### שיוך מג"ב — מסמך מסוג שונה

«סימולצית שכר מגב» אינו מכיל סכומי שכר כלל. הוא טבלת שיוך שאומרת איזו **רמת
פעילות** חלה בכל מרחב ותפקיד; הסכום עצמו מגיע מטבלאות השכר. המערכת מחברת בין
השניים, ואומרת במפורש היכן החיבור אפשרי והיכן לא:

```bash
python3 -m salary_calc.cli --magav-matrix          # טבלת כיסוי מלאה
python3 -m salary_calc.cli --sector 'ימ"מ' --role 'לוחם מג"ב [קבוצה6 ]' --seniority 2
```

מתוך 78 תאים: **12 ניתנים לתמחור** (לוחם מג"ב, שקבוצת השכר שלו מצוינת במפורש
כ-6 ורמות הפעילות שלו זהות לטבלת השכר), **54 חסרי נתון** ו-12 ריקים.
כל תא חסר מחזיר סיבה ספציפית ולא מספר משוער — ראו «מה חסר» למטה.

## איך מחושב השכר

### נקודות עוגן
כל ערך בוותק 0/1/2/3 (ובמנהלים 0/1/2/2.8) נלקח **כפי שהוא** מקובץ המקור.
המערכת לא מחשבת אותו מחדש ולא מעגלת אותו — בדיקה אוטומטית מוודאת שכל אחת
מ-392 נקודות העוגן מוחזרת בדיוק כפי שהיא מופיעה בטבלה.

### ותק ביניים
ותק שאינו נקודת עוגן (למשל 2.5 שנים) מחושב ב**אינטרפולציה לינארית** בין שני
העוגנים הסמוכים. בנקודות העוגן עצמן האינטרפולציה מחזירה את הערך המקורי במדויק.

### מעבר לוותק המרבי
מעל הוותק הגבוה שבנתונים המערכת מבצעת **אקסטרפולציה** לפי שיפוע המקטע האחרון,
ומסמנת את התוצאה כהערכה (כוכבית + אזהרה). זו אינה נתון מהסימולציה.

### תוספות
- **בל"מ ייעודי תחנות — 710 ₪:** תוספת לשוטרי תחנה. הערך אינו מוקלד ידנית אלא
  נגזר ממסמך מחוז ירושלים, ובדיקה אוטומטית מוודאת שהוא משחזר את המסמך בכל
  ארבע רמות הוותק ובשני התפקידים.
- **בל"מ שקלית — 270 ₪:** כבר מגולמת בערכי הבסיס שבסימולציות.
- **החזר הוצאות אישיות — 344 ₪:** מתועד לדרגת רס"ר בלבד. כשמבקשים תצוגה ללא
  הוצאות אישיות עבור רשומה שדרגתה אינה מתועדת, המערכת **לא מנחשת** — היא
  משאירה את הערך כולל הוצאות ומציגה אזהרה.

## בסיסי הצגה — שימו לב

הקבצים אינם אחידים, והמערכת שומרת על ההבחנה במקום לטשטש אותה:

| מסלול | בסיס |
|---|---|
| מקצועות שטח | **כולל** הוצאות אישיות |
| מנהלים | **ללא** הוצאות אישיות |
| תחנת לוד | **ללא** הוצאות אישיות |
| שיוך מג"ב | כמו מקצועות השטח (**כולל**) |

הבסיס מוצג ליד כל תוצאה. אין להשוות מספרים בין מסלולים בלי ליישר את הבסיס.

## אומדן הנטו

מודול **רשות ונפרד** (`salary_calc/tax.py`), כבוי כברירת מחדל.

נתוני המקור הם ברוטו בלבד — אין בהם שום מידע על ניכויים. האומדן מבוסס על מדרגות
מס הכנסה וביטוח לאומי **כלליות** (`config/tax_params.json`), ולכן:

- אינו מביא בחשבון הסדרים ייחודיים לשוטרים (ביטוח לאומי, פנסיה תקציבית, זיכויים ייעודיים).
- אינו כולל זיכויים אישיים מעבר לנקודות הזיכוי שמזינים ידנית.
- **אינו תחליף לתלוש שכר.**

הפרמטרים יושבים בקובץ JSON נפרד כדי שניתן יהיה לעדכן אותם בתחילת כל שנת מס
בלי לגעת בקוד. יש לאמת אותם מול לוחות רשות המסים והביטוח הלאומי לפני הסתמכות.

## אי-התאמות בקבצי המקור

`python3 tools/verify_sources.py` משווה ערכים שמופיעים ביותר ממקום אחד ומדווח
על פערים. נכון להיום נמצאו שלושה פערי עיגול של ±1 ₪ **בקבצי המקור עצמם**:

- בלש לא בתחנה, ותק שנה: מסמך ירושלים 11,417 ₪ מול מצגות הרפרנטים 11,416 ₪.
- רמת פעילות א' בוותק 3: 11,211 ₪ מול 11,212 ₪ בין מתפ"א לבין ש"י/מג"ב
  (הסדרות זהות בשלוש נקודות הוותק האחרות).

אלה אינם באגים בחישוב. המחשבון מציג בכל מקרה את הערך כפי שהוא מופיע בקובץ
שממנו נשאב, ולא "מתקן" את המקור.

## בדיקות

```bash
python3 -m unittest discover -s tests -v     # או: make test
```

41 בדיקות:

- **נאמנות למקור** — כל 392 נקודות העוגן (שטח, מנהלים, לוד) מוחזרות בדיוק.
- **תוספת התחנה** — משחזרת את מסמך מחוז ירושלים ערך בערך.
- **אינטרפולציה** — מדויקת בעוגנים, לינארית ביניהם, מסמנת אקסטרפולציה.
- **ולידציה** — צירופים לא קיימים נכשלים עם הודעה שמפרטת מה כן קיים.
- **שיוך מג"ב** — כל תא במטריצה הוא או מתומחר או מוסבר; אין תא שנכשל בשקט.
- **התאמת JS↔Python** — מריצה את קוד החישוב של העמוד ב-Node על ~1,700 צירופי
  קלט ומשווה מול מנוע הפייתון, כולל ההחלטה "אי אפשר לתמחר". בלי זה קל מאוד
  ששני המנועים יתפצלו בשקט ויציגו מספרים שונים לאותה בחירה. אם Node אינו
  מותקן הבדיקה מדלגת ולא נכשלת.

## מבנה הפרויקט

```

config/tax_params.json   פרמטרי מס לאומדן הנטו — לעדכון שנתי

tools/build_web.py       הזרקת הנתונים לתבנית ← index.html
tools/verify_sources.py  דוח אי-התאמות בין קבצי המקור

salary_calc/engine.py    מנוע החישוב
salary_calc/tax.py       אומדן נטו (רשות)
salary_calc/cli.py       ממשק שורת פקודה

web/template.html        התבנית (כאן עורכים עיצוב ולוגיקת JS)
web/index.html           התוצר — נוצר אוטומטית, לא לערוך ידנית

tests/                   בדיקות + בדיקת התאמה בין המנועים
```

## מה חסר כדי לתמחר את כל טבלת שיוך מג"ב

`make magav` (או `--magav-matrix`) מדפיס את הפירוט המלא. חמש הסיבות:

| # | חסר | תאים | מה יפתור |
|---|---|---|---|
| 1 | טבלת שכר לקבוצה 7 (לוחם ימ"ס) | 4 | סימולציה לקבוצת שכר 7 במקצועות השטח |
| 2 | קבוצת שכר לתפקידים «קצין לוחם ייעודי» ו«מיועד ללוחם מג"ב» | 24 | לאיזו קבוצה/טבלה הם משתייכים |
| 3 | «דף מקצוע» שאליו המסמך מפנה | 9 | הקובץ עצמו |
| 4 | קבוצת שכר למנהלות/מטה, ורמת «ג» בטבלאות המנהלים | 12 | איזו קבוצה 1‑8, ומה משמעות «ג» |
| 5 | שיוך «חוקר» ממרחב מג"ב למחוז בטבלאות החוקר | 5 | מיפוי מרחב → מחוז |

הערה נוספת: טבלת השיוך אינה מזכירה ותק או גמול השתלמות. אלה נבחרים בנפרד
במחשבון, ומוכפלים על רמת הפעילות שהטבלה קובעת.
